# Security policy

## Report privately

Do not open a public GitHub Issue for a suspected vulnerability.

Use GitHub private vulnerability reporting:

1. Open this repository's **Security** tab.
2. Select **Advisories**.
3. Select **Report a vulnerability**.

Include the affected version or commit, a minimal reproduction using synthetic data, potential impact, and any suggested mitigation. Do not include credentials, personal data, customer information, or data taken from a live system.

If private vulnerability reporting is unavailable, do not disclose the issue in
public. Open a Feedback issue containing only the statement that private security
reporting is unavailable; wait for the private channel to be restored before
sharing any technical details.

## Scope

Reports should concern code maintained in this repository. Dependencies and deployment environments may follow separate reporting processes. Testing must stay within systems and data you own or are explicitly authorized to test; this repository does not authorize testing of any third-party or production system.

The maintainer will assess reports and coordinate remediation and disclosure when appropriate. No response or resolution time is guaranteed.
